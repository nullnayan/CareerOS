# Source tools implementation and prerequisites — 2 November 2026

This report supersedes historical source implementation counts, not the operating rule: personal discovery stays paused. No personal database was opened, no existing records or settings were changed, and no frontend/backend/worker/Docker service was started, stopped or restarted. All ingestion and workflow tests use disposable SQLite. Primary-source research and employer board-page inspection do not constitute a personal job search or an observed live collector check.

## Review fixes — 2 November 2026

All four review findings are fixed:

- Workday returns already-fetched details when the execution budget expires and resumes at the first unprocessed offset. Zero-progress windows remain retryable; partial-page signatures still detect a provider ignoring offsets. Network and schema failures retain their existing failure behavior.
- Reviewed-export description and permission confirmations reset when a different file is loaded or the selected rows change. Successful import also clears both confirmations.
- Reviewed exports retain original salary provenance. Explicitly estimated amounts stay unverified throughout ingestion and reassessment; description-derived advertised pay retains its description evidence rather than becoming source-field evidence. Text explicitly labelled as estimated pay is not promoted to advertised pay.
- Excessively nested JSON becomes a validation error (HTTP 422) for preview and commit rather than an unhandled exception.

Validation after these fixes: **236 backend tests passed, 3 skipped** (existing opt-in compiler cases); separate production build passed all 21 routes. ## Completed implementation

- Executable employer setup endpoint `/jobs/sources/employer`, with persistent configuration, exact public URL validation, explicit access review, idempotency, source health, existing ingestion/ranking and scheduler checkpoints. Setup does no network discovery. No migration or dependency installation.
- Workday external CXS transport: fixture-tested implementation, not a supported Workday public API or verified live integration. Exact employer site root required; no guessed tenants. One search and up to eight detail requests per batch, checkpoint recovery, repeated-page detection, preserved first-page signature plus bounded recent history, malformed/empty response diagnostics. No catalogue-size quota; continuations remain paced by the existing scheduler. A 75-second budget is checked before requests; an in-progress socket can take its 20-second timeout beyond that. No missing-job closure is inferred from a CXS window or capped/unstable total. Relative labels and startDate are not presented as publication dates. Workday salary is not inferred.
- Taleo RSS profile: explicitly published feed required, forced excerpt completeness, warning about the documented ten-item search window, no absence-based closure. SAP SuccessFactors published XML profile: common jobtitle/applyurl/jobtype/expirationdate mappings. Oracle Recruiting and iCIMS profiles consume an employer-published XML/JSON/JobPosting feed only; their authenticated APIs are NOT implemented. All four are tested feed routes, not evidence that any employer has supplied a feed.
- Pinned public HTTPS transport now supports internal JSON POST requests and bounded conditional GET caching. Public DNS/IP validation, TLS hostname verification, no redirects, no cookies/auth, 8 MB body limit and Retry-After handling remain enforced. Credential query URLs are rejected. Cache validators reuse the existing bounded cache; no stale success after failures.
- Offline JobSpy-compatible CSV/JSON preview and selected-row import for LinkedIn, Indeed, Glassdoor, ZipRecruiter, Bayt, Naukri, BDJobs and HelloWork. This is an actual export normalizer/import workflow, not a background scraper. Maximum 2 MB / 200 preview rows / 100 selected commit rows. Source-domain validation, per-row errors, deduplication, original source provenance and attribution, advertised salary fields only, geography notes, and explicit description-completeness confirmation. Preview performs no database writes. Imported sources remain manual/disabled. JobSpy itself is not installed or invoked, and its community support does not establish platform permission. See [community README](https://github.com/speedyapply/JobSpy). No proxy or paid service added.
- Bulk ingestion preloads occurrences, canonical URL/fingerprint identities, revision keys and matches in 300-parameter chunks. Pending-object maps preserve autoflush=False deduplication; parent rows flush before dependents under enforced foreign keys. Assessments compute once per changed canonical job. Closure checks also use bulk queries. A 1,200-job first/repeated ingestion test bounds SELECTs at 30 per execution, and checks no reassessment while paused. This is a synthetic regression gate, not a production throughput guarantee.
- Four additional primary board-page mappings: [Twilio/Greenhouse](https://job-boards.greenhouse.io/twilio), [CRED/Lever](https://jobs.lever.co/cred), [ServiceNow/SmartRecruiters](https://careers.smartrecruiters.com/ServiceNow), [Microsoft AI/Greenhouse](https://job-boards.greenhouse.io/microsoftcorporation). Directory now has 15 boards; these four are opt-in, excluded from default setup. Microsoft AI is not the complete Microsoft catalogue. No old PhonePe/Postman slug reused; Meesho stays excluded from defaults. Existing 13 configured free connections were not modified.
- UI separates implementation state, connection state, required inputs and per-connection observed health. All 45 register entries and all employer candidates remain visible, including unresolved mappings.

## External prerequisites that prevent full automatic-source completion

- Workday needs each employer's exact external site and access review before connection. The fixture-tested transport has no newly verified live employer deployment.
- Taleo/SAP/Oracle/iCIMS need exact employer-published feed URLs. iCIMS vendor API credentials and Oracle enterprise access are separate authorized integrations, not normal student/jobseeker login. No credentials should be pasted into chat.
- LinkedIn, Wellfound, Internshala and other restricted/unverified boards need a permitted export or collection contract before unattended collection. Free jobseeker browsing does not supply that contract. FreshersNow's copying restrictions also prevent treating its public page as an automatic export.
- [ZipRecruiter's official MCP documentation](https://www.ziprecruiter.com/partner/documentation/mcp-connector/) now describes search without end-user OAuth, but only US/Canada, five results per call and limited offsets. A supported backend transport endpoint and reuse contract are still required to integrate it into CareerOS; no endpoint was guessed. It is not an India-wide feed.
- Instahyre's documented ATS integration is a paid employer-admin candidate-export product, excluded from this free candidate discovery scope. HackerRank's official MCP is employer assessment/candidate tooling, not a candidate jobs catalogue.
- Complete automatic coverage across all named platforms and every employer is NOT complete. The register records the exact unresolved route instead of representing those sources as working collectors. A broad independent market-recall benchmark also remains outstanding; synthetic scaling tests do not measure market recall.

## Loading the changes

Reload backend/worker code yourself in your existing terminals when ready. Use the existing frontend development hot reload or your normal production build workflow. No migration or Docker restart is required. Do not click Search jobs until you want personal discovery to resume; merely opening Jobs or configuring Sources does not start it.
