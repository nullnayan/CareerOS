# OSS discovery integration — Part 2

**Latest update, 3 November 2026:** See [SEARCH_PIPELINE_FIXES.md](SEARCH_PIPELINE_FIXES.md) for the current search/filter behavior and two-page LinkedIn/Naukri verification. It supersedes the historical limits and incomplete verification below. Relevance controls/ranking are removed; JobSpy uses 20-result batches, overlapping pages continue when progressing, and the 15-minute cutoff is removed. Source experience is retained, with 0–10-year and 1/3-day filters. Instahyre was verified without a proxy. Cross-process cancellation and registered ATS-to-browser format fallbacks are implemented. Unresolved website-specific access/profile issues still remain.

Date: 3 November 2026. Source access coverage remains incomplete; the open-source engine is now implemented as the default code path. Existing service processes were not restarted, so their in-memory code may still be the prior version until the user reloads them.

## What changed

- `JOB_DISCOVERY_ENGINE=oss` is the code default. `legacy` additionally requires `JOB_LEGACY_ENABLED=true`. Old collectors, source rows, enablement values, checkpoints and histories are retained. No personal database/settings were opened or changed during this work.
- Shared fetch dispatch rejects legacy collection in OSS mode. Legacy setup mutations/default connection actions and source toggles are rejected in OSS mode. Old source rows are marked archived and excluded from current discovery, worker setup and search coverage totals. Legacy status collectors cannot run in OSS mode. There is no automatic legacy fallback.
- Discovery tasks carry an engine tag. Tasks created by old code without one are treated as legacy and rejected by the OSS worker. Replaced queries cancel pending old discovery tasks; generation/pause checks discard stale results before ingestion. Automatic scheduling respects the persistent discovery pause.
- OSS source setup is idempotent and separate from searching. The new `/jobs/oss` and `/jobs/oss/connections` routes expose/save the registered upstream options. `/jobs/oss/employer` accepts exact public ATS-host employer URLs and saves them for local ats-scrapers resolution; unsupported URLs fail explicitly during setup or resolution. Setup does not search or enable recurring automation.
- The coordinator chooses a single upstream tool per source, rotates role/location combinations through query-bound cursors, and returns the existing ingestion contract. Up to three fetch tasks run per batch, with a single active Crawl4AI task and per-domain serialization. A search continuation chain is bounded to approximately 15 minutes plus the current batch; remaining work is reported rather than silently dropped.
- JobSpy, local ats-scrapers, the local Omkar wrappers and Crawl4AI are the only OSS retrieval paths. There are 39 predefined connection options, including profiles that remain gated; this count is not a count of working sources. Users can add supported ATS-host boards separately.
- The frontend defaults to the OSS setup panel. It hides legacy setup controls, shows runtime interpreter presence separately from source verification, exposes source errors/cooldowns, supports source toggles and exact employer-board setup, and retains read-only archived connections. All 47 inventory targets and 51 employer candidates remain inspectable. Manual imports and application history remain available.

## Repairs made during review

1. Omkar within-page pagination previously marked the first slice's whole page as already seen, preventing remaining slices from being read. Signatures are now retained only on page completion; repeated subsequent pages still stop. Detail retrieval now follows the current slice rather than repeatedly detailing its first rows. A failed/budget-limited detail no longer breaks the result array and falsely advances beyond its missing rows.
2. ATS output previously stopped at the first limited set with no continuation. The local runner now pages a bounded, versioned snapshot through query-bound cursors. Snapshots expire after one hour; expiry/replacement restarts from row zero rather than skipping a new catalogue's rows. Disk snapshots are bounded to 12 files of approximately 16 MB each; oversized matched catalogues require a narrower query. Source acquisition still has a 24-request ceiling and a supervised timeout. Details are retrieved per batch. These are limits, not proof of exhaustive source coverage.
3. Crawl4AI previously could emit only the first part of a result page and advance to the next page. It now carries a within-page offset before advancing, including detail retrieval for that slice. Generic dynamic pages still do not guarantee a stable source snapshot.
4. Local-model extraction previously accepted an invented description when a different description quote existed on the page. Description text must now match its quoted evidence, and AI output remains an excerpt rather than being automatically marked complete. Structured-data nesting is bounded.
5. Source errors returned inside discovery task results are now surfaced in search status as well as individual source health.

## Remaining coverage blockers and limits

- JobSpy's eight boards have real registered wrappers and can be explicitly connected; Part 1's permission uncertainty is retained, and live access was not reclassified as verified. Do not read their available setup buttons as evidence of working LinkedIn/Naukri collection on this network. Errors or access blocks are surfaced by the source.
- Wellfound and Internshala remain gated by the existing access review. Instahyre's selected upstream implementation requires a proxy, which is excluded. Superset has no verified public search route. Their buttons remain disabled; no automatic collection is claimed.
- Unstop, Cutshort, Foundit, Cuvette and named company profiles retain their recorded challenges, timeouts or partial/unverified search routes. Generic query-parameter profiles do not demonstrate search semantics, full pagination, graduate hiring or regional coverage.
- Cognizant, TCS, Infosys, Wipro, Accenture and Deloitte do not all have verified end-to-end fresher search coverage. Exact supported employer boards can be supplied through ATS setup, but that does not make unknown mappings correct. The ledger preserves these outstanding prerequisites.
- Snapshot caching currently applies to ATS catalogue reuse. Other collectors retain their durable database observations/cooldowns and do not claim a general shared fresh-result cache.
- Pause/replacement prevents stale ingestion; an already running collection can continue until its hard runtime deadline before its result is discarded. There is not an immediate cross-process browser cancellation channel. Browser work remains bounded, but cancellation latency is a remaining improvement.
- Fallback selection is explicit per source. There is no automatic switch from an unsuccessful ATS site into an unverified browser profile, no arbitrary generated scraper execution, and no hidden legacy fallback.

The software integration is materially implemented and tested, but universal source access is not achieved. Source-specific public search/profile work and external access constraints remain; report them separately from installed tooling.
